# 唱歌工作室 · 完整说明

> 这是 `dsh-singing-studio` 的完整使用文档。快速安装和功能概览见 [README](../README.md)。

DSH Web UI 插件：安装环境 → 训练 / 选择音色 → 上传整首歌 → 分离人声/伴奏 → RMVPE 分析 F0 → 八度规划 → 用 RVC 或 SoulX-Singer SVC 生成翻唱。整体只有四个页面：环境安装、RVC训练、制作台、设置。

## 功能

- 时间轴 F0、舒适区/极限区音域带、越界阴影、覆盖率热力条。
- 乐句切分：点乐句高亮对应 F0，并可只播放该句；播放条可切换原曲 / 翻唱。
- 网易云搜歌与下载：免费歌直接下；会员/版权歌可填 MUSIC_U Cookie。
- 制作台歌曲库：显示已下载歌曲、分析次数和已翻唱版本；翻唱列表按歌曲列出并显示对应歌名，可以直接试听 / 下载，支持搜索、分页和按生成时间排序。
- 多任务生成队列：可以连续加入多个生成任务，完成一个会弹应用内提醒（允许时也发系统通知）。
- 成品本地缓存：同一分析 + 音色 + 后端 + 八度方案 + 渲染参数只生成一次，重复点生成直接复用。
- 自绘播放条：点任意位置或拖动都能跳转并继续播放；可在原曲 / 翻唱之间切换，翻唱支持在已缓存的多个八度方案之间选择试听。
- 每个八度方案单独缓存成品：方案表有「成品」列，可一键试听某个方案的结果，不用重新生成。
- 切换试听版本时，时间轴的处理后曲线 / 变调轨 / 覆盖率热力条，以及右上角的音域 / 覆盖率摘要会同步切换。
- 全局 / 分段 / 乐句三层互斥的八度规划（动态规划），只移人声八度，伴奏不动。
- RVC 音色训练：填唱歌数据目录，按「切分 → F0 / HuBERT → 训练 → 索引 → 音域 Profile」一条龙跑完；进度条显示每个 epoch 的拟合度、mel loss 和预计剩余时间。
- 两个换声后端：
  - **RVC**：已训练音色，速度快。
  - **SoulX-Singer SVC**：零样本，用参考音频克隆音色，无需训练。
- 跨平台依赖检查、下载、环境准备。
- RVC / SoulX 常驻 Worker：模型加载一次，后续分析和渲染复用；自动 CUDA / CPU。
- 环境未就绪时禁止歌曲分析、八度处理和生成。

## 环境要求

- Node.js >= 22.13（DSH 自带）。
- Python 3.10–3.12（用于创建两个独立 venv；插件会自动寻找）。
- 磁盘：首次准备约 7–9 GB（两个 venv + RVC 资源 + SoulX 模型 + 分离模型）；训练底模另加约 208 MB。
- GPU：NVIDIA CUDA 时自动装 CUDA 轮子并使用 GPU；否则 CPU。
  - Apple Silicon 使用 CPU。SoulX 的 STFT 目前在 MPS 上不可用，所以不走 MPS。

## 安装为 DSH 插件

安装方式见 [README 的「安装」一节](../README.md#安装)：插件市场搜索安装（npm，走 `registry.npmmirror.com`）、手动填包名安装，或本地 `npm pack` 后安装 tarball / 源码目录。

安装后侧栏出现「唱歌」。**第一次打开会直接停在「环境安装」页**：点「一键安装」即可；环境没就绪时会自动把用户带回这一页。

## 界面

只有四个页面：

| 页面 | 内容 |
|---|---|
| 环境安装 | 依赖清单、设备、Worker 常驻、一键安装（带预计剩余时间）、手动下载清单 |
| RVC训练 | 顶部三个模式标签：训练新音色 / 导入已有模型 / SoulX 音色；训练数据、常用参数、高级参数、训练进度和结果在同一张表单里，历史模型在右侧 |
| 制作台 | 歌曲库、已翻唱版本、多任务队列；「音高时间轴」页顶部是歌曲 / 音色 / 后端选择和「分析 F0 / 生成方案 / 生成歌曲」，右侧并排是八度与乐句高级设置，中间是时间轴和方案对比 |
| 设置 | 分轨速度、通用行为与上传限制；安装路径由插件自动管理 |

环境安装页只放一键安装和下载兜底；RVC训练页用顶部标签在「训练新音色 / 导入已有模型 / SoulX 音色」之间切换，一次只显示一套表单；制作台的歌曲库页管歌曲、翻唱和网易云搜歌；SoulX 参数在「SoulX 音色」标签的高级参数里；音高时间轴页管选歌 / 分析 / 方案 / 生成，以及八度和乐句设置；设置页放通用行为和上传限制。

页面内不再重复写长段说明：参数和卡片标题在悬停 / 聚焦时显示 tooltip，不再给每个字段加 ⓘ，页面层级交给顶部导航、训练模式标签和「制作台」标签页。设置页不再提供代理入口；需要时可在插件数据目录的 `settings.json` 里设置 `proxy`。

训练和生成都在后台跑，切页或切到其他 DSH 面板不会中断；切回来会恢复歌曲、分析、方案、成品、播放位置和队列进度。试听条只在「音高时间轴」页的时间轴下方显示；切到歌曲库或其他页面会自动暂停并保留进度。

## 环境安装

「环境安装」页会检查：

| 项 | 说明 |
|---|---|
| 系统 Python | 3.10–3.12 |
| RVC Python | venv + torch/torchaudio/librosa/faiss/transformers/av/parselmouth |
| RVC 代码 | 插件内置 `vendor/rvc`，缺了会复制 |
| RVC 资源 | `rmvpe.pt`（181 MB）+ `hubert_base`（189 MB） |
| RVC 训练代码 | 插件内置 `vendor/rvc/train`，缺了会复制 |
| RVC 训练依赖 | TensorBoard + scikit-learn + matplotlib（训练可选） |
| RVC 训练底模 | `pretrained_v2/f0G48k.pth` + `f0D48k.pth`（约 208 MB，训练可选） |
| ffmpeg | 系统有就用；没有就装 `imageio-ffmpeg` |
| 人声分离 | `audio-separator` + `onnxruntime` + BS-Roformer 模型 |
| SoulX Python | venv + torch 2.2/transformers 等 |
| SoulX 代码 | 插件内置 `vendor/soulx` |
| SoulX 模型 | `model-svc.pt`（约 2.6 GB） |
| Whisper base | SoulX 的内容编码器（约 150 MB） |

音色模型不计入环境安装检查：环境就绪后，在「制作台」选择已有音色，或先去「RVC训练」训练一个。

点「一键安装 / 继续安装」会按顺序创建 venv、安装依赖、下载缺失文件；进度条会显示当前阶段和预计剩余时间。已有文件会跳过，下载走 `.part` 文件断点续传——中途退出后再点一次即可继续。

「依赖清单」和「手动下载 / 离线安装」默认都是收起的，首次使用只需要点「一键安装」，不用先看一长串依赖。如果某个文件下载失败，页面会自动展开「手动下载」、高亮失败项并给出它的下载线路和目标路径；把已经下载好的文件拖进该项的虚线框（或点击选择），插件会校验扩展名/大小并直接放进目标路径，成功后自动刷新清单。也可以复制目标路径自己放置，再点「重新检查环境」。

环境优先用 uv 管理：检测到 uv 就用 `uv venv --seed` 建 venv、`uv pip install` 装依赖；没有 uv 或 uv 执行失败时自动退回 `python -m venv` + `pip`，两种方式装出来的环境一致。Python 包默认走清华 PyPI 镜像、失败回退官方 PyPI；PyTorch 的 CUDA 轮子例外，仍走官方索引（清华没有 pip 版 CUDA 轮子）。所有下载地址的完整清单见 [环境下载地址总表](DOWNLOADS.md)。

### 安装位置

默认 **managed** 模式：代码、venv、模型都由插件放在
`~/.dsh/plugins-data/singing-studio/runtime/`，不需要手动配置。

开发和调试时如果要复用项目里已有的 `.venv-rvc`、`third_party/rvc`、`model/SoulX-Singer`，
可以改插件数据目录下的 `settings.json`（`mode: existing` + `projectRoot`）；界面上不再暴露路径配置。

### GPU / CPU

- 安装 PyTorch 时检测 `nvidia-smi`：有 NVIDIA 就装 CUDA 轮子，否则 CPU。
- Worker 启动时再检测 `torch.cuda.is_available()`：CUDA 可用就用 GPU，否则 CPU。
- 未预加载时推理设备显示「auto（待加载）」；加载后按 Worker 实际设备显示「auto（GPU）」或「auto（CPU）」，并显示模型是否常驻。
- 模型加载后进程保持存活；后续分析和渲染不再重新加载。
- 在「设备与常驻」卡片里可以「预加载 RVC / SoulX」：加载中显示小圆圈百分比，随时可以点「暂停」终止加载；加载完成后同一位置显示 100% 和「卸载模型」，只停掉对应后端的 Worker 进程，另一个后端不受影响。
- 「预加载 RVC」加载的是设备与常驻里「音色模型」下拉选中的 RVC 音色；这个选择与制作台的当前音色共用，模型库有多个时只加载选中的一个。RVC 已加载其他模型时，按钮会变成「加载所选模型」，不需要先卸载。实际生成时也会自动切换到当前请求使用的模型。

## 音色模型和 Profile

发行包不包含任何人的音色模型。使用前需要：

1. 放一个 RVC `.pth` 到 `modelsDir`。
2. 准备 `profiles/<model-id>.json`，至少包含：
   ```json
   {
     "id": "my_voice",
     "label": "我的音色",
     "p1": 180, "p5": 210, "p50": 340, "p95": 520, "p99": 590,
     "promptWav": "path/to/reference.wav"
   }
   ```
   `promptWav` 是 SoulX-SVC 的参考音频（5–15 秒干净干声，优先演唱片段）；如果 Profile 没填，会使用插件已保存的默认参考音频（`settings.json` 里的 `soulxPromptWav`）。
3. 分析/规划会读取这些值作为音域带。

`profiles/` 可以放插件目录（内置）或插件数据目录（训练自动生成），两处会合并读取，同 id 时数据目录优先。发行包不带任何示例音色；字段说明和模板见 [`profiles/README.md`](../profiles/README.md)。

训练完成后自动生成的 Profile 在插件数据目录：

```text
~/.dsh/plugins-data/singing-studio/profiles/<模型id>.json
```

训练结果 JSON（`training/<任务id>.json`）里的 `profilePath` 也指向这个文件。训练日志目录 `runtime/rvc/logs/<模型id>/1_16k_wavs/` 保留了 16 kHz 训练切片；Profile 丢失时可以用这些切片按 RMVPE 重新统计音域，不需要原始数据集。

### SoulX 零样本音色（不需要 `.pth`）

在「RVC训练」页顶部选择「SoulX 音色」标签：

1. 填参考音频路径（会写入这个音色的 Profile；留空则使用已保存的默认参考音频），可填 5–30 秒干净、少混响、无伴奏的目标音色人声；
2. 可选填显示名，点「创建音色」；
3. 插件用 RMVPE 统计参考音频的音域，写出 `profiles/<音色id>.json`，其中：
   - `kind: "soulx"`；
   - `model: ""`（没有 RVC 权重）；
   - `promptWav` 指向参考音频；
   - `p1 / p5 / p50 / p95 / p99` 为音域百分位。
4. 创建后自动切到 SoulX 后端并选中该音色；可以直接在「音高时间轴」做八度调整和生成。

面板底部还有默认折叠的「高级参数」：设备、扩散步数、CFG、参考截取；修改后点「保存参数」。

这类音色只用于 SoulX 后端；如果切到 RVC，会提示切换后端或换一个 RVC 音色。参考音频和 Profile 只保存在本机，不会上传。

## 训练 RVC 音色

在「RVC训练 → 训练新音色」标签填一个装着唱歌音频的文件夹（支持子目录，wav / flac / mp3 / m4a / ogg），起一个模型名，点「开始训练」即可。常用参数只有采样率和总轮数；版本、批大小、切片、F0 方法、设备、底模、索引都在「高级参数」里默认折叠。

1. 自动切分音频、提取 F0（RMVPE）和 HuBERT 特征。
2. 默认配置是 48k / v2 / 20 轮 / 批大小 4；展开「高级参数」可以改版本、批大小、保存间隔、切片长度、F0 方法、并行进程、设备、预训练底模、检索索引和「每 N 轮存可试听模型」。
3. 每个 epoch 更新一次拟合度：`100 × (1 − e^(−18 / mel loss))`，只反映训练趋势，不代表绝对音质。
4. 训练完成自动构建 faiss 索引（可选），并从训练集采样 RMVPE 生成音域 Profile；结果区显示轮数、切片、拟合度和 mel loss，点「复制模型路径」即可拿到 `.pth` 的完整路径。
5. 如果开了「每 N 轮存可试听模型」，训练结果卡不再列出轮次按钮；点「用这个音色去制作」会自动在最终模型和已导出的轮次中选拟合度最高的一份，通过 `/train/use` 复制成当前音色（`models/<模型名>.pth`），Profile 沿用同一次训练生成的那份，然后进入制作台。每份约 55 MB，默认关闭。
6. 表单右侧的「历史模型」会扫描 `assets/weights/*_e*_s*.pth`，按模型名分组：组头显示模型名和训练完成时间，组内只列拟合度前 2 轮；每行显示「第 N 轮」和拟合度百分比，点一下切换当前音色，缺 Profile 的会标出来。只有「当前音色 + 当前轮次」那一行会高亮。

训练进程收到取消时，会先让训练子进程在当前 step 结束、把 G/D 检查点写进 `<rvcDir>/logs/<模型名>/` 再退出（最多等 180 秒，超时才强杀）；CPU 训练较慢，建议用 NVIDIA GPU。训练期间「制作台」仍可用已有音色分析 / 生成，任务会排队等训练结束后执行；训练进度只在「RVC训练」页显示。同名训练没跑完时，再次点「开始训练」会弹「上次训练未完成」，可以「继续训练」——复用已经切好的片段、F0 和 HuBERT 特征，并从最新检查点接着跑——或者「重新开始」清掉重训；已完成的训练再同名开跑则会问是否清除旧的训练目录、权重、模型和音域 Profile。训练出的 Profile 默认没有 `promptWav`；如果要给这个音色用 SoulX-SVC，可以补一段 5–15 秒的干净参考音频，或直接在 Profile 里补 `promptWav`。

## 使用

1. 侧栏「唱歌」，先在「环境安装」页一键安装。
2. 去「RVC训练」训练自己的音色（或直接用已有音色）。
3. 打开「制作台」：歌曲库会列出已下载的歌和已翻唱版本，点「音高时间轴」进入工作区。
4. 在「音高时间轴」顶部选歌、选音色：分析 F0 → 生成八度方案 → 选方案 → 生成歌曲。已有同音色分析的歌会自动复用分析结果。
5. 生成任务会进入队列，可连续加入多个；完成一个会提醒。「已翻唱的版本」会列出所有歌的成品并标明歌名，可直接试听 / 下载；列表支持按歌名 / 方案 / 后端搜索、6 条一页分页，以及「最新 / 最早」按生成时间排序。
6. 「音高时间轴」页顶部左侧是歌曲 / 音色 / 后端选择和三个生成按钮，右侧并排是「八度与乐句高级设置」；时间轴卡片右上角是音域 / 覆盖率摘要，下面是方案对比。高级设置调完保存后重新分析生效。

## 人声分离速度

设置页 →「人声分离 → 分轨速度」：

- **标准（4）**：模型默认的重叠预测窗口数，质量优先。
- **快速（2）**：预测窗口数减半，分轨大约快一倍，接缝瑕疵的风险略高。
- **极速（1）**：最快，接缝处更可能出现断续或金属感，建议先用一首歌试听再批量用。

改动只影响之后新做的分轨；歌曲目录里已有 `vocals.wav` / `instrumental.wav` 时会直接复用，不会重新分离。换一首未分离的歌，或清掉该歌曲的两个分轨文件后重新分析，才会按新设置重跑。

Apple Silicon 上 audio-separator 已经自动使用 MPS，不需要额外设置；`--mdxc_batch_size` 对 Roformer 模型没有明显加速作用。分离耗时主要取决于重叠窗口数和歌曲长度，和 CPU/GPU 占用没有直接关系。

## 已有模型：路径、格式与 Profile 校验

在「RVC训练」页顶部选择「导入已有模型」标签：

- 「已有模型权重路径」可以填 `.pth` 文件，或包含 `.pth` 的模型包目录，例如 `models/dafeiyu-rvc-singing-v1`；相对路径从插件目录算。
- 「训练数据」与「训练新音色」标签共用同一个路径；如果模型还没有 Profile，填训练数据后点「生成 Profile 并加入」，会用 RMVPE 统计音域并自动生成 Profile，**不需要重新训练**。
- 「已有 Profile（可选）」可指定现成的 Profile；留空时自动查找模型目录或插件 `profiles/` 目录里的同名 `.json`。
- 「模型权重」输入框支持从模型库下拉选择已有 `.pth`，也可以直接填入或粘贴路径；校验结果里会显示路径、文件格式和 Profile 状态，并可复制模型 / Profile 路径。
- 校验会检查：`.pth` 是否为 PyTorch zip 检查点（`data.pkl` 和权重张量）、可选的 `model_metadata.json` 是否与文件一致、Profile 是否包含 p1 / p5 / p95 / p99 且顺序为 `p1 ≤ p5 < p95 ≤ p99`，以及 Profile 的 `id` / `model` 是否与模型匹配（不一致会提示，导入时归一化）。
- 格式和 Profile 都通过后可以「加入模型库」：复制 `.pth` 到模型目录、同名 `.index` 到 RVC 索引目录，并把 Profile 写成插件数据目录里的 `<模型id>.json`。

缺少 Profile 时仍可复制模型路径；可以直接用训练数据生成，或把 `<模型id>.json` 放到模型包目录 / 插件 `profiles/` 目录。参考模型包 `models/dafeiyu-rvc-singing-v1` 自带 `.pth`、匹配 `.index` 和 `model_metadata.json`，但需要另配音域 Profile 才能用于分析。

## 网易云搜歌

「制作台」里可以搜歌名或歌手，下载后自动加入歌曲库。已经下载过的歌会在搜索结果里标「已下载」，按钮变成「打开」，点一下直接跳到歌曲库里的那首歌，不会重复下载。免费歌不需要登录；会员 / 版权歌在「制作台设置 → 网易云下载」里填网易云的 `MUSIC_U` Cookie（只保存在本机，不会回显）。

## 数据目录

`~/.dsh/plugins-data/singing-studio/`

- `songs/<id>/`：上传源、`vocals.wav`、`instrumental.wav`
- `analysis/`、`plans/`、`renders/`
- `profiles/`：训练自动生成的音域 Profile
- `training/`：训练任务的结果 JSON 和日志
- `runtime/`：managed 模式的代码、venv、模型
- `settings.json`、`history.json`

## 已知限制

- SoulX 接入的是 **SVC（换声）**，不是 SVS；不能改词重唱，音域宽度问题仍靠八度规划缓解。
- 只允许八度折叠；对 loli 这类音域很窄的模型，覆盖率提升有限。
- SoulX CPU 推理较慢：122 秒整首 4 步约 2.5 分钟，16 步约 8–10 分钟。
- 发行包不包含音色 `.pth`，需要按实际音色准备并确认授权。
- 首次准备依赖网络；模型默认优先走 `hf-mirror.com`，失败才回退 `huggingface.co`；国内也可在插件数据目录的 `settings.json` 设置 `proxy`。安装中断后可以继续，已下载完成的文件不会重下。
- 同一时间只有一个后台任务真正占用模型，其他生成任务会排队；队列完成后会提醒。
- RVC 训练在 Apple Silicon / CPU 上很慢；拟合度是由 mel loss 换算的经验值，只用于看趋势。
- 训练后自动生成的 Profile 采样训练集音频；如果训练集混入伴奏或混响，音域统计会偏高。

## 平台差异

| 平台 | Python | GPU | 说明 |
|---|---|---|---|
| macOS | 3.10–3.12 | CPU | Apple Silicon 不走 MPS（SoulX STFT 不支持）；RVC/SoulX 用 CPU |
| Windows | 3.10–3.12（`py` 启动器） | NVIDIA CUDA / CPU | 自动使用 `Scripts\python.exe`、`Scripts\audio-separator.exe`、`ffmpeg.exe` |
| Linux | 3.10–3.12 | NVIDIA CUDA / CPU | 自动使用 `bin/python`；需要 NVIDIA 驱动才能用 CUDA 轮子 |

安装器会自动识别平台路径、venv 结构、ffmpeg 可执行文件；不需要手工改路径。若系统 Python 不在 PATH，可在设置里填 `systemPython`。
